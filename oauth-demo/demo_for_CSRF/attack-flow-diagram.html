🔐 OAuth 2.0 CSRF Attack Flow Comparison

❌ VULNERABLE FLOW (No State)

1
👹 Attacker: Initiates OAuth flow
GET /authorize?client_id=APP&redirect_uri=... ❌ NO STATE PARAMETER
↓
2
🔐 OAuth Server: User logs in and authorizes

Attacker login: attacker@email.com

↓
3
👹 Attacker: Receives authorization code
/callback?code=ATTACKER_CODE

Attacker intercepts and saves the code

↓
4
👹 Attacker: Crafts malicious URL
https://app.com/callback?code=ATTACKER_CODE

Sends this link to victim via email/chat/etc

↓
5
👤 Victim: Clicks malicious link

Victim is logged into the app

↓
6
💻 Client App: Processes callback
❌ NO STATE VALIDATION! Code is from attacker but app doesn't know Exchanges code for access token Gets attacker's user info
↓
7
👤 Victim's Session: Linked to attacker's OAuth
session.user = { email: "attacker@email.com", name: "Attacker User" }
❌ CSRF ATTACK SUCCEEDS!
Victim's account linked to attacker's OAuth

✅ SECURE FLOW (With State)

1
👤 Victim: Clicks "Login with OAuth"
state = generateRandom() // "abc123..." session.state = state
↓
2
💻 Client App: Redirects with state
GET /authorize?client_id=APP&redirect_uri=... &state=abc123...
↓
3
🔐 OAuth Server: User authorizes

Victim login: victim@email.com

↓
4
🔐 OAuth Server: Redirects with code + state
/callback?code=VICTIM_CODE &state=abc123...
⚡ ATTACKER TRIES ATTACK ⚡
5
👹 Attacker: Sends malicious link
/callback?code=ATTACKER_CODE &state=wrong_or_missing
↓
6
💻 Client App: Validates state
✅ STATE VALIDATION: receivedState = "wrong_or_missing" session.state = "abc123..." if (receivedState !== session.state) { return "CSRF Attack Detected!" }
↓
7
🛡️ Protection: Request rejected
HTTP 403 Forbidden Error: "State validation failed"
✅ CSRF ATTACK BLOCKED!
State validation prevents account linking

📚 Legend & Key Concepts

👹
Attacker: Malicious user trying to link victim's account to their OAuth
👤
Victim: Legitimate user who falls for the attack (without state parameter)
🔐
OAuth Server: Authorization server (e.g., Google, Facebook)

🔑 State Parameter:

  • Purpose: Prevent CSRF attacks in OAuth flow
  • Generation: Cryptographically secure random string
  • Storage: Stored in user's session on client app
  • Validation: Must match between request and callback
  • Lifetime: Single-use, expires after validation

⚠️ Why Vulnerable Code Fails:

Without state parameter, the client app has no way to verify if the authorization code in the callback came from the user who initiated the OAuth flow. An attacker can inject their own code, and the app will happily process it, linking the victim's session to the attacker's OAuth account.

✅ How State Parameter Protects:

The state parameter creates a cryptographic binding between the OAuth initiation and the callback. Since the state is stored in the victim's session and is unpredictable to the attacker, any callback with a mismatched or missing state is immediately identified as a CSRF attack and blocked.
