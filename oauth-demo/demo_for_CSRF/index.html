❌ Vulnerable Version Demo

Quick Start:

# Terminal 1 - OAuth Server node server-vulnerable.js # Terminal 2 - Client App node client-vulnerable.js

Steps to Reproduce Attack:

  1. Mở Attacker Page:
    Navigate to http://localhost:4000/attacker-page
  2. Get Authorization Code:
    Click "Start OAuth Flow" và login: attacker@email.com / attacker123
  3. Copy Code:
    Từ URL callback, copy authorization code
  4. Generate Malicious Link:
    Paste code và click "Generate CSRF Attack Link"
  5. Victim Clicks Link:
    Open http://localhost:4000 và paste malicious link
  6. Observe Result:
    ❌ Attack thành công! User info hiển thị attacker's email
⚠️ Kết quả:
Victim's session bị link với OAuth account của attacker. Attacker có thể access dữ liệu của victim!

✅ Secure Version Demo

Quick Start:

# Terminal 1 - OAuth Server node server-secure.js # Terminal 2 - Client App node client-secure.js

Steps to Try Attack (Will Fail):

  1. Mở Attacker Page:
    Navigate to http://localhost:5000/attacker-page
  2. Try Same Attack:
    Thực hiện các bước giống như vulnerable version
  3. Victim Clicks Link:
    Paste malicious link vào browser
  4. Observe Result:
    ✅ Attack BỊ CHẶN! Error: "CSRF Attack Detected"
✅ Kết quả:
State validation chặn attack thành công. Error message hiển thị rõ ràng và request bị reject.

🎯 Key Learning Points

✅ State Parameter là BẮT BUỘC trong OAuth 2.0 Authorization Code Flow

✅ State phải cryptographically random và đủ dài (32+ bytes)

✅ State phải lưu server-side (session), không lưu client-side

✅ Validate state trong callback là critical security check

✅ State phải one-time use và có expiry time

✅ Không có state = Vulnerable to CSRF attack 100%
