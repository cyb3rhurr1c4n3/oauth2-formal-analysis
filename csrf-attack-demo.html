CSRF Attack Demonstration

This demonstrates a working CSRF attack on OAuth flow without state parameter validation.

How This CSRF Attack Works:

The CSRF vulnerability allows an attacker to trick a victim into linking their OAuth account to the attacker's application session.

Real-world scenario: Attacker is logged into App.com, starts "Link OAuth Account", captures URL, sends it to victim. Victim clicks and authorizes, thinking they're linking their own account, but actually links to attacker's App.com profile.

In this demo: Since we're using same browser/session for simplicity, we'll show the vulnerability by demonstrating that authorization completes WITHOUT validating who initiated it.

Step 3: See the Vulnerability

After authorization, notice:

  • The callback URL has NO state parameter to verify
  • The server accepts ANY authorization code
  • No way to detect if user initiated this OAuth flow
  • In real attack: victim's account links to attacker's session

Why This Works:

  • No state parameter to verify the request origin
  • Server-side session stores the token from ANY authorization
  • Attacker's browser shares the same session cookie
  • When victim authorizes, it completes attacker's OAuth flow
  • Attacker's session now has victim's account access

How State Parameter Would Prevent This:

// Attacker initiates OAuth
const attackerState = generateRandomState();
saveToSession(attackerState);

// Victim clicks malicious link
// Victim's browser has DIFFERENT session, DIFFERENT state

// Callback validates:
if (receivedState !== sessionState) {
    throw Error('CSRF detected!');
}
// Attack blocked!
