Secure OAuth Implementation Security Tests

Testing all security mitigations against common OAuth vulnerabilities

About This Security Test Suite

This page tests the secure OAuth implementation (port 3001/4001) to verify that all vulnerabilities have been properly mitigated. Each test attempts an attack that works on the vulnerable version but should be blocked here.

Prerequisites

Make sure both secure servers are running:

# Terminal 1 - Secure Auth Server (port 4001) cd auth-server-secure node server.js # Terminal 2 - Secure Client (port 3001) cd client-app-secure node server.js

Security Test Suite

Test 1: XSS Token Theft (localStorage)

Vulnerability: Tokens stored in localStorage can be stolen via XSS attacks.

Mitigation: Secure version uses httpOnly cookies (inaccessible to JavaScript).

Test 2: Authorization Code Interception (No PKCE)

Vulnerability: Authorization codes can be intercepted and used without PKCE.

Mitigation: Secure version enforces PKCE (code_challenge/code_verifier).

Test 3: CSRF Attack (No State Parameter)

Vulnerability: No state validation allows CSRF attacks.

Mitigation: Secure version validates state parameter.

Test 4: Open Redirect Vulnerability

Vulnerability: Auth server accepts any redirect_uri.

Mitigation: Secure version validates redirect_uri against whitelist.

Test 5: Client-Side Token Exposure

Vulnerability: Tokens visible in browser/Network tab.

Mitigation: Secure version handles tokens server-side only.

Security Summary

Attack Vector Vulnerable (Port 3000) Secure (Port 3001)
XSS Token Theft localStorage - Exploitable httpOnly Cookies - Blocked
Code Interception No PKCE - Exploitable PKCE Enforced - Blocked
CSRF Attack No State - Exploitable State Validation - Blocked
Open Redirect Any redirect_uri - Exploitable Whitelist - Blocked
Token Exposure Client-Side - Visible Server-Side - Hidden
